# Feature Specification: M1 单批次情景计算

**Feature Branch**: `main`（未配置分支 hook，规格目录独立于分支）

**Created**: 2026-10-24

**Status**: Complete — 17 项功能需求与 8 项成功标准已全部通过完整门禁验收（`artifacts/m1/m1-gate-final/report.json`）。

**Input**: User description: "同步文档状态并 M1"；在 M0 已正式通过的基础上，按项目路线定义单批次情景计算的首个可发布版本。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从一个集合批次得到可解释的情景 (Priority: P1)

作为集合预报分析者，我希望把同一模型、起报、有效时刻和区域内的成员场分成若干情景，查看每个成员的归属、各情景的平均场、代表成员和成员占比，以便检查集合中的主要差异。

**Why this priority**: M0 已验证数据传递；本阶段的主要价值是产生实际情景结果，并保留足够信息解释结果。

**Independent Test**: 直接提交带成员身份的固定矩阵和显式计算配置，检查完整输出，不依赖数据下载、查询宿主或历史批次。

**Acceptance Scenarios**:

1. **Given** 合法的成员矩阵和配置，**When** 计算情景，**Then** 每个输入成员恰好属于一个非空情景，所有成员均保留，结果可关联到原任务和配置。
2. **Given** 一个已完成的情景，**When** 查看其摘要，**Then** 能得到原始物理单位和特征顺序下的成员平均场、该情景内最接近聚类中心的真实成员、成员数、成员占比及离散程度。
3. **Given** 多个成员与中心等距，**When** 选择代表成员，**Then** 按输入成员顺序选择最先出现者，重复执行保持一致，并说明距离所在的计算空间。
4. **Given** 不同身份但数值相同的成员或部分常量特征，**When** 仍满足配置的有效性条件，**Then** 保留其身份和权重，不静默删除成员或特征。
5. **Given** 无效配置、秩不足或不能形成所需情景数的输入，**When** 计算，**Then** 明确失败，不自动减维、减簇或输出伪成功结果。

---

### User Story 2 - 确认原生结果与参考结果一致 (Priority: P1)

作为算法维护者，我需要在相同输入和可比较的初始化条件下核对原生计算与已冻结的参考流程，区分算法错误、随机初始化差异和无意义的编号差异。

**Why this priority**: 迁移正确性决定结果是否可信；只有最终图像相似或目标函数接近不足以证明迁移完成。

**Independent Test**: 使用 M0 冻结真实样本和具有已知分组的合成样本，独立执行参考与待验收计算，并运行包含正反例的比较检查。

**Acceptance Scenarios**:

1. **Given** M0 的同一冻结输入及二维投影、三簇参考配置，**When** 执行迁移对照，**Then** 消除簇编号差异后成员分区与 M0 基线一致，可比数值满足固定容差，中间结果和配置可追溯。
2. **Given** 用于定位算法差异的共享初始中心及相同停止规则，**When** 对照两种实现，**Then** 按成员身份检查标准化、投影几何、中心、成员分区和目标函数；共享初始化的运行单独标识，不能覆盖原 M0 随机初始化基线。
3. **Given** 同一输入、配置、初始化和声明环境，**When** 在三个独立进程中重复计算，**Then** 成员分区、代表成员和情景摘要一致，可比数值满足容差。
4. **Given** 两份结果仅有情景编号置换或等价投影基变化，**When** 比较，**Then** 能判为等价；成员归属变化或数值超出容差时必须拒绝通过。

---

### User Story 3 - 在查询中批量计算真实集合情景 (Priority: P1)

作为查询使用者，我希望通过现有查询环境将已准备的真实集合数据按任务提交，得到可保存和继续分析的情景结果；不同任务和并发查询之间必须互不影响。

**Why this priority**: 计算需要进入可执行的数据流程，才能成为首个可用版本。

**Independent Test**: 在目标查询环境加载产物，从真实样本构造有序成员输入并计算，和直接计算结果对照；另用小型任务验证批量隔离及错误恢复。

**Acceptance Scenarios**:

1. **Given** 可从记录步骤恢复的真实区域集合样本，**When** 经查询路径完成成员排序、计算及结果保存，**Then** 得到与直接计算等价的结果，记录来源到输入的字段映射，任务和成员身份均可核对。
2. **Given** 成员数、特征数和配置各自合法的多个任务，**When** 批量执行，包括任务行数和单任务成员数分别超过一次内部处理批量的情况，**Then** 所有结果完整且隔离，不截断、重复或混合。
3. **Given** 至少两个独立连接同时处理任务，**When** 与串行结果比较，**Then** 按任务及成员身份得到等价结果，不共享可变的拟合状态或随机状态。
4. **Given** 每类非法输入，**When** 在同一连接执行“合法、非法、合法”序列，**Then** 非法调用说明原因和位置或层级，前后合法调用均成功；混合合法与非法任务的查询不能被记录为部分成功。
5. **Given** 无参考计算工具且断网的最小运行环境和本地样本，**When** 加载并计算实际情景以及执行错误恢复，**Then** 正常完成，证明参考环境不参与核心运行。

---

### User Story 4 - 按文档复现结果并判断是否可发布 (Priority: P2)

作为维护者或新的验证者，我需要可执行示例、明确的支持范围、资源测量和逐项验收记录，以便重建结果并判断这个版本是否具备发布条件。

**Why this priority**: 可发布意味着别人能够复现和核对，而不仅是在作者的工作目录中成功运行。

**Independent Test**: 在全新检出目录按指南构建、恢复样本并执行示例，核对证据；资源测量和验收报告可分别复核。

**Acceptance Scenarios**:

1. **Given** 全新检出目录与文档声明的前置条件，**When** 按步骤构建、恢复输入和运行示例，**Then** 无需未说明的个人路径或全局环境即可得到等价情景；缓存和网络依赖明确记录。
2. **Given** 固定真实输入，**When** 分别计算 1、10、100 个任务，**Then** 每个规模均完成并记录耗时、峰值内存、任务形状、线程设置和测量边界，串并行结果等价。
3. **Given** 所有验收材料，**When** 汇总阶段结论，**Then** 每项功能要求和成功标准都有可定位证据；任何必要检查失败或未执行都不能判定 M1 整体通过。

### Edge Cases

- 输入任意嵌套层为 NULL、空成员列表、空或重复成员 ID、空特征、维度不一致、NaN 或正负无穷：明确拒绝，报告层级或成员位置。
- 配置缺失、计数参数非整数、迭代/重启次数不为正、停止容差为负或非有限、有效秩阈值不为正或非有限，以及维度或簇数超出 FR-003 的范围：明确拒绝，不依赖工具隐含默认值。
- 不同成员数值相同但身份不同：允许保留；可区分成员向量总数不足以形成所需簇数则拒绝。
- 常量特征：保留，在标准化后贡献为零；整体有效秩不足时拒绝。
- 保留投影子空间内部的符号或基旋转：按几何等价比较；保留与舍弃维度的边界退化导致子空间无法确定时，明确失败。
- 聚类产生空簇、达到迭代上限仍未收敛或中间计算出现非有限值：明确失败，提供诊断，不把未完成拟合当成功结果。
- 多个成员与中心等距：采用固定输入顺序决胜；单任务的情景编号不代表跨批次持续身份。
- 同一任务成员列表重排：输出仍绑定正确身份；只承诺固定有序输入的重复性，不承诺依赖成员顺序的初始化在任意重排下产生同一分区。
- 来源、单位、网格顺序或时间语义不一致：在准备环节拒绝合并；数值计算不能从矩阵值推断这些元数据。
- 不支持的宿主版本或平台：明确报告支持边界，不能关闭版本检查冒充兼容。
- 冻结载荷已存在时支持离线计算；首次恢复必须回源时，记录来源和获取条件，不承诺从清单在断网环境生成缺失数据。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 必须计算单模型、单起报、单有效时刻、单变量、单区域的成员空间场情景。每个任务包含有序且唯一的成员身份、共同长度的非空特征向量及显式配置；调用方保留任务身份和时间、网格、单位等样本语义。
- **FR-002**: 首版必须提供与 M0 参考语义一致的逐特征标准化、按解释方差从大到小保留主成分的无白化投影，以及最小化簇内平方欧氏距离和的迭代聚类流程。标准化以成员总体均值和总体方差为准，常量特征的尺度按 1 处理；不隐式添加空间权重或删除重复向量。
- **FR-003**: 必须显式记录投影维度、聚类数、初始化、重启次数、停止规则、迭代上限和有效秩判定规则。支持的投影维度为不小于 1 且不超过标准化后有效秩的整数；聚类数为不小于 2 且不超过成员数及可区分向量数的整数。重启次数与迭代上限须为正整数，停止容差须有限且非负，有效秩阈值须有限且为正；初始化及停止规则必须是已声明支持的选项。首个验收配置沿用二维投影和三簇；无效或不支持的配置明确拒绝，不能静默修改。
- **FR-004**: 每个成功任务必须返回完整成员归属及每簇成员数、成员占比、原始物理空间的成员平均场、真实代表成员和离散诊断。平均场由该簇原始成员向量逐特征求均值；成员占比为该簇成员数除以任务成员总数。所有成员等权，不能将该占比称为校准概率。
- **FR-005**: 代表成员必须来自所属簇，按投影后聚类空间中到该簇中心的平方欧氏距离选择；距离相同则选择输入顺序最先出现者。离散诊断至少包括每簇平方距离和以及全任务总和；同时报告用于这些量的空间和配置，不把投影中心误标为物理场。
- **FR-006**: 结果及验收材料必须能关联输入内容身份、成员顺序、配置、算法版本和运行环境。必须提供标准化均值与尺度、有效秩、投影及解释方差信息、聚类中心、总平方距离和、迭代次数和收敛状态，使维护者可以定位差异；具体结果组织方式留给技术规划。
- **FR-007**: 必须在 M0 冻结真实矩阵上与原参考基线对照，并在可比较的共享初始化下增加算法步骤对照。共享初始化及所需的坐标对齐必须记录；不同实现相同的随机种子不能单独充当初始化一致的证据。不得覆盖原始 M0 输入、配置或验收结果。
- **FR-008**: 比较规则必须在验收结果生成前冻结：成员分区消除编号置换后完全一致；可比数值满足 `abs(actual - reference) <= 1e-8 + 1e-6 * abs(reference)`。投影先验证子空间和成员间距离，逐项坐标及中心仅在同一对齐规则下比较；物理平均场独立比较。比较器必须接受编号置换和等价投影，拒绝成员错分及超容差数值。改变规则必须版本化并重跑，不得事后放宽门槛维持通过。
- **FR-009**: 固定有序输入、配置、初始化及声明环境下，三个独立进程的分区、代表成员、成员数和成员占比必须一致，可比数值满足 FR-008。串行、批量和至少两个独立连接并发的结果也须等价，任务间不得共享可变计算状态。
- **FR-010**: 本规格边界情况中的非法输入和数值退化必须明确失败并提供原因及位置或层级；不能静默补值、丢弃成员、减维、减簇或伪造收敛。失败不得终止宿主，同一会话后续合法调用须成功；混合合法/非法任务的查询整体判失败。
- **FR-011**: 必须提供查询调用入口，保持任务与成员身份绑定，支持多任务及跨内部批量边界，结果可保存并继续查询。函数名、类型签名、数据转换方式和错误映射在技术规划中确定，不把 M0 诊断往返当作 M1 聚类。
- **FR-012**: 必须提供至少一条真实来源到统一有序输入、查询计算及结果保存的端到端示例，记录字段映射、时间和单位、成员角色、数据及配置校验值。沿用 M0 的真实样本及恢复途径即可满足数据接入门禁；其他来源或 OM 路径不能在未实测时宣称已支持。
- **FR-013**: 必须提供覆盖可解释分组、不同身份的重复向量、常量特征、代表成员距离并列和全部非法类别的合成用例；每类至少一个。真实样本验证与合成验证分别记录，不能互相替代。
- **FR-014**: 核心计算必须能脱离查询宿主独立执行，不访问网络、隐式读取历史状态或调用外部参考工具。必须在断网且无参考工具的最小环境中实际执行情景计算和同连接错误恢复，不能仅凭依赖清单或诊断往返判定隔离成功。
- **FR-015**: 必须记录构建、参考、数据准备及运行环境的具体版本和重建步骤，提供目标平台的构建与实际加载检查。优先复用 M0 的版本组合；有变化须记录原因和重跑范围。全新检出目录复跑所用缓存、网络及同机限制必须说明。
- **FR-016**: 必须测量固定真实输入下 1、10、100 个任务的墙钟时间和峰值内存，分别标记冷启动与已加载范围，记录输入/输出规模和线程设置，并核对串并行正确性。能够分离的转换与计算成本分别报告，不能分离的部分明确标记；不设未经测量的吞吐承诺。
- **FR-017**: 必须提供可执行示例、复跑指南及逐项覆盖所有功能要求和成功标准的验收报告。所有必要项实际通过后才能判定 M1 完成；失败、未执行、未覆盖平台及数据使用限制均须明确记录。

### Key Entities *(include if feature involves data)*

- **计算任务**：一个批次的一组有序成员和共同特征，关联任务身份、模型、起报、有效时刻、变量、网格、单位和特征版本。
- **成员输入**：不可分离的成员身份与特征向量；数值相同的不同成员仍是独立成员。
- **情景配置**：定义标准化、投影、聚类、初始化、停止和有效性规则的一组显式参数，具有可追溯版本。
- **情景结果**：单任务内的成员分区及各簇摘要；簇编号只在本次计算内有效。
- **代表情景**：一个簇的物理平均场、真实代表成员、成员数、成员占比和离散程度。
- **计算诊断**：用于解释数值有效性、投影保留信息、聚类误差和收敛状态的量及其计算空间。
- **迁移对照与验收记录**：绑定输入、配置、版本、预期、实际结果和逐项状态的可复核证据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少一份包含完整产品成员集合的真实区域输入可从记录途径恢复，并完成从数据准备到可保存情景结果的流程。M0 的 50 成员、9 特征样本在二维投影、三簇配置下产生 3 个非空情景，50 个成员全部且仅归属一次。
- **SC-002**: 每个成功用例的成员数之和等于输入成员数，成员占比之和在绝对误差 `1e-12` 内为 1；每簇平均场满足 FR-008 的容差，代表成员属于本簇并符合最短距离和并列规则，离散诊断可从成员与中心独立重算。
- **SC-003**: 冻结真实样本及全部约定的合成对照用例中，100% 成员分区在消除编号置换后与相应参考一致，全部可比数值满足固定容差。比较器的等价正例全部通过，故意错分和超容差反例全部被拒绝。
- **SC-004**: 三个独立进程重复、串行与至少两个连接并发、跨任务行及跨成员批量边界的合法用例全部得到等价结果，零成员丢失、零任务串扰。
- **SC-005**: 规格定义的非法数据、无效配置及数值退化类别每类至少一个用例，100% 明确拒绝，每个失败后的同会话合法计算均成功；混合任务查询没有被记为部分成功。
- **SC-006**: 在无参考工具且断网的最小运行环境中，真实输入的完整情景计算、结果核对与错误恢复全部通过。
- **SC-007**: 1、10、100 个任务规模均完成正确计算，三种规模各有耗时、峰值内存和测量范围记录，无法分离的成本明确标记，结果与单任务对照等价。
- **SC-008**: 一名验证者或一个独立的全新检出目录能按指南重现真实样本结果及错误恢复；证据索引覆盖 100% 功能要求和成功标准，所有必要项通过后才给出整体通过结论。

## Assumptions

### 已确定的项目约束

- 核心计算使用原生 Rust 或 Rust 包，独立于 DuckDB；DuckDB 扩展提供 SQL 调用入口。这些是既有用户约束，具体数值包、函数签名和模块划分属于技术规划。
- Python、CDO、wgrib/wgrib2 等仅用于准备数据或独立参考验证，不参与 core 的构建、部署或核心运行路径。
- DuckOMO 负责 OM 数据路径；core 不绑定来源格式。本阶段沿用已经验证的真实输入路径，不以新增数据源为算法迁移前提。
- 当前 constitution 仍为未填写模板，不从示例推导治理要求；后续正式原则如有变化需复核规格。

### 范围与默认假设

- M0 已正式验收通过。其冻结输入、比较规则和版本组合是 M1 的起点；M1 尚未实现，规格质量通过不代表算法或发布门禁通过。
- 初始验收沿用 Linux aarch64 和 M0 已验证宿主版本。更多平台、WASM、扩展签名及发布渠道不属于本次验收；首个可发布版本不等于本次自动发布到外部渠道。
- 默认复用 M0 的 WeatherBench2 IFS ENS 2020-01-01 00 UTC 起报、+24h、2 米气温、50 个扰动成员、3×3 网格、K 单位样本。控制成员未包含，不推定其他产品的控制成员与扰动成员可直接同权合并。
- 源 float32 数值先准确还原，再提升到参考计算精度；不直接把源数值的十进制文本当成未经还原的高精度观测。
- 基线配置沿用 M0 的二维投影、三簇及其显式初始化和停止设置，不宣称这是最佳情景数。有效秩阈值初始沿用 `1e-10`；更改必须说明原因并版本化验证。
- 样本派生数值的再分发许可尚未落实，继续只提交清单、恢复步骤及可分发材料；已有本地冻结副本可离线计算，首次从清单恢复需要声明的来源访问条件。
- 跨起报匹配与持续身份、分裂合并、多变量或时序轨迹、多模型加权、缺失值插补、概率校准、最优情景数研究及预测收益验证留在后续阶段。
- 不新增常驻服务、通用调度器、通用格式适配平台，也不全面改造旧下载器或恢复所有教程。
