## User Scenarios & Testing *(mandatory)*

### User Story 1 - 获得身份明确的固定集合样本 (Priority: P1)

作为研究者，我需要可长期复查的小型真实区域集合样本，明确每个值属于哪个成员、网格点和预报批次，避免算法比较使用不同来源、不同起报或持续更新的数据。

**Why this priority**: 输入身份不明或不可恢复时，后续参考结果无法作为证据。

**Independent Test**: 不运行聚类或扩展，仅检查样本清单、内容校验值、成员、空间点、单位和时间，离线恢复成员矩阵。

**Acceptance Scenarios**:

1. **Given** 具有明确起报和成员身份的真实来源，**When** 冻结单模型、单变量、单区域、单起报、单有效时刻的数据，**Then** 保留所选产品声明的完整成员集合，每个成员对应相同的有序空间点集合。
2. **Given** 冻结样本及清单，**When** 远端更新或不可访问，**Then** 仍能离线恢复相同矩阵并核对内容校验值。
3. **Given** 只有均值、单点序列、缺失成员或无法证明起报身份的数据，**When** 检查资格，**Then** 明确报告不满足项，不将其算作真实区域集合样本通过。
4. **Given** 无法随仓库分发的样本，**When** 提供复现材料，**Then** 清单说明取得与恢复途径、校验值及使用限制；无法为预期验证者提供合规恢复途径时，门禁保持未通过。

---

### User Story 2 - 重复得到同一份参考计算结果 (Priority: P1)

作为算法维护者，我需要在固定输入上复现现有教程的核心计算，保存可检查的配置、中间结果和成员分组，作为后续原生实现的对照。

**Why this priority**: 图表不能替代 M1 所需的数值基线。

**Independent Test**: 从固定有效矩阵开始运行参考流程，不依赖数据下载或扩展，比较三个独立进程中的结果。

**Acceptance Scenarios**:

1. **Given** 同一输入、环境和配置，**When** 在三个独立进程中重复计算，**Then** 成员分区一致，数值符合预先声明的容差，输出可追溯至输入校验值。
2. **Given** 两份结果仅改变分组编号或等价投影的符号，**When** 比较，**Then** 不误报表示差异；真正改变成员分区或可比较数值时能够检出。
3. **Given** 缺失、非有限值或不满足参考计算条件的输入，**When** 验证，**Then** 明确失败，不静默补值、删除成员或标记成功。
4. **Given** 输入或配置变化，**When** 生成结果，**Then** 使用新的证据身份，旧结果不被无提示覆盖或沿用。

---

### User Story 3 - 确认计算调用边界可安全使用 (Priority: P1)

作为查询使用者，我需要在声明环境实际加载独立扩展，传入带身份的成员与特征，收到保持身份、顺序和值的结果；错误输入必须明确失败。

**Why this priority**: 在算法移植前排除加载和数据交换问题，避免以文档支持代替实际可用性。

**Independent Test**: 用已知预期值的微型合成任务做往返，不依赖真实天气样本或聚类实现。

**Acceptance Scenarios**:

1. **Given** 可加载产物及匹配的宿主环境，**When** 新建会话、加载并调用，**Then** 实际返回对应成员、特征及任务身份，不能仅以编译成功替代验证。
2. **Given** 多个成员数和特征长度不同但各自合法的任务，**When** 批量调用，**Then** 结果完整且互不混合，成员与特征保持绑定，包括跨内部处理批量的任务。
3. **Given** 不同嵌套层的非法数据，**When** 调用，**Then** 当前调用失败并说明原因；不返回伪成功结果，同一会话随后仍能完成有效调用。
4. **Given** 固定合法任务，**When** 串行及并发执行，**Then** 按任务身份得到一致结果，并记录处理时间、峰值内存和测量范围。
5. **Given** 未安装参考计算工具的最小运行环境，**When** 加载扩展并往返数据，**Then** 仍然成功，证明验证工具没有进入该运行路径。

---

### User Story 4 - 判断是否具备进入 M1 的条件 (Priority: P2)

作为维护者，我需要把要求、执行记录和结论关联起来的报告，判断哪些证据支持进入 M1，哪些问题仍阻塞。

**Why this priority**: 局部通过、设计建议和未执行检查不能算作阶段完成。

**Independent Test**: 对照规格及证据索引复核报告；即使某个实验失败，也能独立判断报告是否准确说明其影响。

**Acceptance Scenarios**:

1. **Given** 检查记录，**When** 汇总，**Then** 每项必要门禁具有通过、失败或未执行状态，关联输入、配置、执行步骤、结果位置及判断依据。
2. **Given** 合成调用检查通过但真实样本未通过，**When** 判断阶段状态，**Then** 报告局部进展，M0 整体仍不通过。
3. **Given** 所有必要门禁通过，**When** 独立复核，**Then** 能按记录重跑并得到相同结论，获得进入 M1 所需的样本契约、比较规则、环境组合及依赖选择依据。

### Edge Cases

- 来源更新、对象失效或内容变化：以冻结副本和校验值为准，不自动用新内容替代旧样本。
- 成员数不同、字符串成员 ID、控制成员：保留清单声明的身份和角色，不硬编码统一成员数，不重复计入控制成员。
- 成员乱序：允许按记录的规则重排；重复身份、重复空间点或成员间点集合不同则拒绝进入参考样本。
- 外层任务、成员项、特征列表或元素为 NULL，以及空任务、空特征、NaN/无穷值：拒绝调用并说明位置或层级，失败后会话仍可使用。
- 任务内特征长度不同：拒绝；不同任务间可使用不同的合法长度。
- 常量特征和数值重复但身份不同的成员：按固定参考策略处理，不静默删除。有效秩不足、聚类数超过成员数或可区分样本数时，明确失败，不静默减少聚类数。
- 单位、网格顺序、时间含义不同：按声明规则规范化并保留原始信息；无法证明对应关系时拒绝合并。
- 分组编号置换、投影符号变化或退化子空间：使用预先声明的等价规则；无法判定时报告未通过，不扩大容差掩盖差异。
- 成员列表超过单次内部处理批量，或任务跨多个批量：分别验证成员数和任务数，不截断或错配。
- 不支持的宿主版本或平台：明确标记，不关闭兼容性检查冒充通过。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 必须冻结至少一份真实区域集合样本，包含单模型、单起报、单有效时刻、近地面气温变量和产品声明的完整成员集合。均值、单点或合成数据不能替代该门禁。
- **FR-002**: 清单必须记录来源及产品版本/快照（若提供）、获取时间、起报与有效时间、成员及控制成员角色、区域与点键、形状、原始/规范化单位、排序及变换规则、内容校验值、使用限制和恢复步骤。
- **FR-003**: 冻结输入必须可离线恢复；自动验证使用的冻结样本数据总量不得超过 100 MiB。大范围原始数据下载和完整归档不属于本阶段。
- **FR-004**: 参考流程必须覆盖现有概率产品教程的核心数值步骤，保存配置、规范化矩阵、可比较中间结果、成员分区及校验信息。默认保留二维投影、三组划分用于复现，不宣称这是最佳算法。
- **FR-005**: 比较规则必须在生成验收结果前固定。默认数值容差为 `abs(actual - reference) <= 1e-8 + 1e-6 * abs(reference)`；成员分区消除编号置换后必须一致，投影按记录的等价规则比较。修改规则须说明理由、产生新证据版本并完整重跑，不能事后放宽门槛保留原通过结论。
- **FR-006**: 必须提供覆盖正向往返和本规格异常输入的微型合成样本。真实与合成样本分别标识和报告，不互相代替。
- **FR-007**: 必须在声明宿主环境实际加载独立产物，完成有序成员及特征往返。本阶段不实现正式聚类，往返或诊断输出不得标为聚类结果。
- **FR-008**: 往返必须保留每个任务的成员身份、顺序、值和长度；多任务、跨内部处理批量及并发执行不得混合、遗漏或重复结果。
- **FR-009**: 非法输入必须使所属调用明确失败，报告原因及可识别的位置或层级；不得静默修复、返回部分成功或终止宿主进程。同一会话随后须能完成合法调用。
- **FR-010**: 必须记录参考工具、宿主、构建工具和依赖的具体版本及复现步骤，使验证者能够重建声明环境，不依赖未说明的个人全局环境。
- **FR-011**: 必须测量固定有效输入下 1、10、100 个任务的时间与峰值内存，并检查串行与并发结果一致性。报告区分已测范围与无法单独测量部分；本阶段不设未经测量的吞吐量承诺。
- **FR-012**: 必须分别检查参考环境与最小调用运行环境；后者不具备参考工具时仍能完成 FR-007 至 FR-009 的正向及错误恢复检查。
- **FR-013**: 必须提供所选来源到统一成员输入的字段映射及一次可复现的真实样本提取证据。其他来源的调查或局部读取不能替代该证据。
- **FR-014**: 报告必须逐项关联 FR-001 至 FR-013 的证据及状态，记录进入 M1 的样本契约、比较规则、验证环境、候选数值依赖的选用/排除理由和未覆盖平台。失败或未执行的必要门禁使整体 M0 保持未通过。

### Key Entities *(include if feature involves data)*

- **冻结集合样本**：单个预报任务的真实数据与离线副本，通过清单确定成员、空间点和时间语义。
- **样本清单**：与数据内容绑定的身份、来源、变换、使用条件和校验依据。
- **参考运行**：固定输入、环境、配置及比较规则的一次执行，保存中间和最终结果。
- **验证任务**：有身份且有序的成员与特征集合，数据与其他任务隔离；非法任务使所属调用失败。
- **验证证据**：输入、步骤、版本、预期结果、实际结果与判断依据。
- **阶段结论**：必要门禁和未覆盖范围的汇总，区分规格准备完成与实现验收通过。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少 1 份真实区域集合输入可离线恢复，冻结样本总量不超过 100 MiB；清单必填信息完整率 100%，成员及空间点集合检查全部通过。
- **SC-002**: 固定输入在 3 个独立进程中的参考运行全部满足 FR-005，成员分区一致，输入、配置和结果可追溯。
- **SC-003**: 所有正向往返用例精确保留任务/成员身份、顺序、值与长度，包含多任务、跨内部处理批量及并发用例，零截断、零串扰。
- **SC-004**: 本规格定义的非法输入类别每类至少有 1 个用例，100% 明确拒绝；每个失败用例之后的合法调用均成功。
- **SC-005**: 完成 1、10、100 个任务规模的时间与内存记录，重跑后确认结果一致；报告不隐瞒未测部分或宣称未定义的性能目标已通过。
- **SC-006**: 证据索引覆盖 100% 功能要求，全部必要门禁通过才给出整体通过。另一名验证者或独立干净环境能按步骤重现 SC-001 至 SC-004。

## Assumptions

### 用户确定的约束

- 核心计算使用原生 Rust 或 Rust 包，DuckDB extension 提供调用入口。这是用户指定约束；具体包、函数签名、数据交换方式和代码结构留给技术规划。
- Python、CDO、wgrib/wgrib2 等仅用于验证或准备参考数据；core 不通过这些工具执行核心算法，也不将其作为构建、运行或部署依赖。
- DuckOMO 是 OM 数据路径；真实样本不强制采用 OM，core 不绑定文件格式，其他来源按相同资格检查判断。

### 范围与默认假设

- M0 交付可复现参考结果与最小调用实验；正式原生聚类移植属于 M1。
- 本机 Linux ARM64 为当前验证环境。其他平台、浏览器、正式发布渠道和稳定对外接口不在本阶段验收范围。
- 默认复现单变量、单时刻的区域气温场，所选样本须支持二维参考投影及三组划分。轨迹、多变量、多起报追踪及最佳算法研究留在后续阶段。
- 优先选择可证明起报、成员与网格身份的开放归档。具体提供商、日期、区域、对象和读取工具在技术规划中选定并冻结，不把某一家 API 或格式作为前提。
- 不要求两家提供商逐值一致，也不把同名模型当作相同输入。
- 无合格真实样本时可继续合成实验，但 M0 整体不得通过；改变该门禁需显式修订规格。
- 不开发通用 Icechunk/GRIB 插件，不全面重写旧下载器，不恢复全部绘图教程；允许借助既有读取能力准备有来源证据的固定输入。
- 不验证概率校准、跨起报身份、分裂合并或交易收益，不把成员占比称为校准概率。
- 当前 constitution 仍为未填写模板，未从示例内容推导治理要求；正式原则后续如有冲突需重新检查本规格。
