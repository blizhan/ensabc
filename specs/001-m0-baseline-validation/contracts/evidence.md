# M0 验收报告接口

本契约定义正式 M0 验收产物；当前 planning spike 的记录可以被引用，但不自动补齐整项要求。

## 输出目录

一次验收写入新的 `artifacts/m0/<run-id>/`，其中至少包含：

```text
environment.json
source-hashes.json
sample-validation.json
reference/run-1.json
reference/run-2.json
reference/run-3.json
reference/comparison.json
exchange.json
measurements.json
minimal-runtime.json
report.json
```

文件可引用其他不可变输出，所有引用均保存路径和 SHA-256。禁止记录凭据或整份机器环境变量；仅列出复现必需的工具版本、平台、线程设置与依赖信息。

## report.json

顶层字段：

| 字段 | 含义 |
| --- | --- |
| `schema_version` | `m0.report.v1` |
| `run_id` | 与输出目录对应的唯一运行身份 |
| `created_at` | UTC 时间 |
| `overall` | `passed`、`failed`、`incomplete` |
| `requirements` | FR-001 至 FR-014，各出现一次 |
| `limitations` | 未覆盖平台、范围及限制 |
| `m1_handoff` | 样本、参考配置、比较规则、版本组合和依赖决策的文档引用 |

每项 requirement 包含 [验证契约](validation.md) 的记录字段。可以由多个案例聚合；任一必要案例失败即该项失败，任何必要案例未运行且无失败则为未执行。总体有失败为 `failed`，无失败但有未执行为 `incomplete`，全部满足才为 `passed`。FR-014 检查报告完整性、引用可解析及聚合规则，不要求报告内容“都是通过”才认为报告结构正确。

正式驱动程序返回码：`0` 仅代表整体 `passed`，`1` 为验证失败，`2` 为证据不完整或执行条件未满足。日志打印不能替代结构化状态。
