# Feature Specification: M2 跨批次情景追踪

**Feature Branch**: `main`（未配置分支 hook，规格目录独立于分支）

**Created**: 2026-10-29

**Status**: Complete (Implemented & Verified)

**Input**: User description: "下一步我们做 M2：跨批次追踪 / 最新的 DuckOMO 接入"；经讨论确认优先做短中期区域 2 米气温集合的跨起报追踪，并接受“WeatherBench2 真实集合 → 固定样本转 OM → 最新 DuckOMO → 单批次情景 → 跨批次匹配”作为首条接入路径。

## Clarifications

### Session 2026-10-29

- Q: 两批情景在门槛内有多种一对一配对方式时，应优先追求什么？ → A: 先最多关联条数，再最小总距离；不引入未关联代价参数。
- Q: 两种配对总距离完全相同时，相关情景是否继承前一批身份？ → A: 按固定决胜规则继承，但关联与身份链标为歧义；接近并列只报告余量，不设拒绝门槛。
- Q: 关联门槛用固定温度差还是相对集合离散的比例？ → A: 相对离散的比例：每对相邻批次的门槛 = 比例系数 × 该对批次的集合离散尺度；匹配计算本身接收已换算的绝对门槛。
- Q: 真实 8 批回放中每批情景数如何设定？ → A: 主结果所有批次固定 3 个情景（沿用 M1 验收配置）；另以 2 个和 4 个情景各回放一次做敏感性对照；情景数变化的匹配行为由合成用例验证。
- Q: DuckOMO 接入是否验收远程读取？ → A: 只验收本地冻结 OM 文件的读取；远程读取与请求合并留到后续。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 判断两次起报的情景是否延续 (Priority: P1)

作为集合预报分析者，我希望对同一有效时刻、相邻两次起报各自得到的情景，按物理场相似程度建立一对一关联，并能看到哪些情景找到了延续对象、哪些因距离过大或竞争失败而未关联，以及每条关联的距离和可替代程度。

**Why this priority**: 这是 M2 区别于 M1 的核心能力；没有可解释、允许拒绝的两批关联，持续身份和历史回放都没有依据。

**Independent Test**: 直接提交前后两批情景的物理平均场、空间权重和匹配配置，与小规模穷举参考逐项核对，不依赖数据下载、查询宿主或历史保存。

**Acceptance Scenarios**:

1. **Given** 两批情景存在明确的一一对应关系，**When** 任意打乱任一侧的情景顺序和本批编号，**Then** 关联到的物理情景、距离和未关联项均不变。
2. **Given** 所有候选距离都超过门槛，**When** 匹配，**Then** 正常返回零条关联、两侧全部未关联及原因，而不是报错或强行关联。
3. **Given** 一个门槛内存在多种一对一组合的输入，**When** 匹配，**Then** 先在门槛允许的候选中取得最多关联条数，再在这些组合中取总距离最小者；不能先强制完全匹配再删除超门槛关联。
4. **Given** 前后两批情景数不同（例如 2→3），**When** 匹配，**Then** 每个情景至多参与一条关联，多出的情景记为未关联。
5. **Given** 存在总距离完全相同的多种最优组合，**When** 匹配，**Then** 结果按声明的规则确定且可重复，同时将相关关联标为歧义，不把决胜规则表述为物理身份证据。

### User Story 2 - 沿多次起报保持情景身份并保存历史 (Priority: P1)

作为分析者，我希望在 4–8 次连续起报中，每个情景都有一个持续身份：延续的情景继承前一批身份，未关联的情景获得新身份，并能查询每一步的距离、未关联项和身份变化原因。

**Why this priority**: 持续身份是“跨批次追踪”对外可见的结果；必须能追溯到每一次相邻关联的证据，而不仅是一列编号。

**Independent Test**: 用合成的多批链（含延续、新出现、结束、缺批）执行完整回放并保存历史，检查身份分配、关联记录和重跑结果。

**Acceptance Scenarios**:

1. **Given** 一组按计划起报序列排列的批次，**When** 回放，**Then** 首批每个情景获得新身份；之后每个已关联情景继承前驱身份，未关联情景获得新身份并记录原因；每个情景恰有一个身份，同一身份在同一批次至多出现一次。
2. **Given** 计划序列中缺少一批或某批计算失败，**When** 回放，**Then** 在缺口处断链，缺口后的情景全部获得新身份并注明“前一计划批次不可用”，不跨过缺口找回旧身份。
3. **Given** 相同的有序输入清单、配置和版本，**When** 在独立进程中重复回放，**Then** 所有情景、关联、距离和身份编号完全相同。
4. **Given** 插入一个批次或修改配置，**When** 重新回放，**Then** 形成新的回放版本并重算整条链，旧版本完整保留；对同一回放版本写入不同内容时明确失败。
5. **Given** 回放中途发生错误，**When** 查看已保存的历史，**Then** 不存在该回放的部分关联、部分身份或半条链，同一会话后续合法回放可成功。

### User Story 3 - 用最新 DuckOMO 读取真实连续起报集合并完成追踪 (Priority: P1)

作为查询使用者，我希望从 OM 格式的真实逐成员集合出发，在同一查询环境中完成读取、单批次情景计算、跨批次匹配和历史保存，并确认读取到的数值与数据来源逐值一致。

**Why this priority**: 用户要求本阶段接入最新 DuckOMO；只有真实逐成员、多起报数据走通完整路径，追踪结果才有实际意义。

**Independent Test**: 从记录的来源恢复 8 个真实批次，转为固定 OM 样本，分别用源解码、独立 OM 读取和 DuckOMO 查询三条路径取值对照，再执行端到端回放。

**Acceptance Scenarios**:

1. **Given** 8 个真实起报批次的 OM 样本，**When** 通过 DuckOMO 读取，**Then** 每批得到 50 个成员 × 9 个格点的完整矩阵，与源解码及独立 OM 读取逐值相同，无重复、缺失或成员折叠。
2. **Given** 同一查询连接，**When** 同时加载 DuckOMO 与本项目扩展，**Then** 能从 OM 读取直接完成情景计算、匹配并保存历史。
3. **Given** 目标版本与对照版本 DuckOMO，**When** 分别执行相同读取和回放，**Then** 成员矩阵与追踪结果完全一致；加载前已核对两者发布包的校验值。
4. **Given** 来源、单位、格点顺序、有效时刻或起报时间不一致的批次，**When** 准备追踪，**Then** 在计算距离前明确拒绝，不依靠数组长度相同放行。

### User Story 4 - 解释真实案例并检查追踪稳定性 (Priority: P2)

作为研究者，我希望看到真实 8 批案例中各情景如何延续、何时断开，以及关联结果对轻微输入扰动和门槛取值的敏感程度，以判断追踪结果是否值得解释。

**Why this priority**: 追踪的价值在于可解释；若轻微扰动就频繁换身份，结果不能用于后续演化分析。

**Independent Test**: 基于冻结的真实样本输出回放报告，并按事先冻结的扰动幅度和门槛范围重复实验，比较关联与身份变化。

**Acceptance Scenarios**:

1. **Given** 真实 8 批回放，**When** 生成案例报告，**Then** 每对相邻批次都列出完整候选距离、关联、未关联项、歧义程度和身份链，所有数值可回溯到输入和配置。
2. **Given** 距离远离门槛和最优组合切换边界的情景，**When** 施加事先声明的轻微扰动，**Then** 该对映射后的关联不变；出生节点对应关系及上游继承关系均不变时，逻辑身份也不变。
3. **Given** 处于门槛或最优切换边界附近的情景，**When** 施加相同扰动，**Then** 报告记录发生的翻转及其距离余量，而不是要求其绝对稳定。
4. **Given** 声明的门槛比例系数范围，**When** 逐一回放，**Then** 报告每个取值下的关联数和身份链变化，不事后挑选门槛以得到期望结论。

### User Story 5 - 按文档复现并判断 M2 是否完成 (Priority: P2)

作为维护者或新的验证者，我需要复跑指南、资源测量和逐项验收记录，以便在全新检出目录重建真实案例与合成验证并判断 M2 是否完成。

**Why this priority**: 与 M0、M1 一致，阶段结论必须由可复核的证据支持。

**Independent Test**: 在全新检出目录按指南恢复样本、转换、读取并回放，核对验收报告与追溯记录。

**Acceptance Scenarios**:

1. **Given** 全新检出目录与声明的前置条件，**When** 按指南执行，**Then** 无需未说明的个人路径即可得到与原运行相同的回放结果；网络和缓存依赖明确记录。
2. **Given** 所有验收材料，**When** 汇总结论，**Then** 每项功能要求和成功标准都有可定位证据；任何必要项失败或未执行都不能判定 M2 完成，M1 原有验收仍然通过。

### Edge Cases

- 某一侧情景列表为 NULL 或为空、本批情景编号重复、平均场长度不一致、含 NaN 或正负无穷：明确拒绝并报告位置。缺批或失败批次通过批次状态表达，不用空情景列表代替。
- 空间权重含负数、非有限值、长度与格点数不一致或总和为零：拒绝。数学定义对权重整体正比例缩放不变。浮点实现须在冻结的合法缩放用例上验证数值一致性；接近门槛或最优匹配切换边界时，必须报告可能由舍入产生的决策变化。
- 距离恰好等于门槛：视为可关联；规则公开且有边界用例。
- 某批集合离散尺度为零或非有限（如全部成员相同）：该对批次的门槛无法确定，明确报错，不退回到固定门槛。
- 有限输入在距离计算中溢出或产生非有限值：报告数值错误，不能当作“距离过大所以未关联”。
- 两侧情景完全相同且无法区分：仍给出确定结果，但相关关联必须标为歧义。
- 前一批未关联的情景：只表示在当前规则下没有后继，不表述为天气情景在物理上消失；当前批未关联也不表述为物理新生。
- 相同成员编号出现在不同批次：不作为情景延续的依据；跨起报的成员之间不存在对应关系。
- 同一预报时效但有效时刻不同的批次：不得互相关联。
- 起报时间重复或非递增、起报加时效不等于共同有效时刻：在准备阶段拒绝。
- 某批单批次情景计算失败（例如秩不足）：该批记为失败并按缺口断链，不自动减少情景数以求成功。
- OM 数据中的缺测值（读取为 NULL）：本阶段样本要求全部格点有限；出现缺测时拒绝该批，不按成员各自删点。
- 同一回放版本被重复写入相同内容：幂等成功；写入不同内容：明确失败，不静默忽略。
- 目标 DuckOMO 版本加载失败或校验值不符：报告失败，不改用未经核对的本地构建冒充。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 必须支持单模型、单变量、单固定区域、单一共同有效时刻下 4–8 次按计划序列连续起报的情景追踪。同一回放版本内每批使用同一份 M1 情景配置独立计算情景；追踪对象是情景，不是成员。真实案例主结果沿用 M1 验收配置（二维投影、每批 3 个情景）。
- **FR-002**: 计算距离前必须确认所有批次的模型、变量、单位、有序格点清单、特征版本和共同有效时刻完全一致，起报时间严格递增，且每批“起报时间 + 预报时效 = 共同有效时刻”。任一不一致在准备阶段拒绝。匹配计算本身不从数值推断这些元数据，这一检查由调用流程负责并留证。
- **FR-003**: 两个情景的距离必须是两者物理平均场（M1 按最终成员归属对原始输入逐格求得的均值）之间的空间加权均方根差，单位与温度单位相同。权重必须显式提供、有限、非负、总和为正并有版本；首个验收配置在规则经纬网格上采用随纬度余弦变化的面积近似权重。距离不得使用各批独立的投影坐标、成员编号、情景编号或成员占比；成员占比仅作为结果展示。
- **FR-004**: 门槛以内（距离小于或等于门槛）的候选构成可关联集合；必须在其中求一对一部分匹配，首要目标为关联条数最多，其次为关联距离之和最小。门槛必须参与求解，不得先求完全匹配再删除超门槛关联。每对相邻批次的门槛等于比例系数乘以该对批次的集合离散尺度：单批离散为全部成员相对该批集合平均场的空间加权均方根偏差（与 FR-003 同一权重和单位），一对批次的尺度取两批离散的算术平均，只使用这两批自身的数据。比例系数必须显式、版本化，并在执行验收前冻结；匹配计算接收换算后的绝对门槛，以便用绝对距离的合成用例独立验证。
- **FR-005**: 每对相邻批次必须返回完整候选距离矩阵与可关联标记、选中关联及其距离、两侧未关联情景及原因（无门槛内候选，或在全局竞争中未被选中）、目标值、两批各自的离散、换算后的绝对门槛，以及匹配配置和算法版本；距离同时以温度单位和相对离散尺度的比值给出。无关联是正常成功结果，不是错误。
- **FR-006**: 每条选中关联必须报告可替代程度：去掉该关联后按同一目标层级重求的最优结果相对当前结果的差距，无替代时以明确状态表示。存在目标完全相同的其他最优组合时，相关关联必须标为歧义。决胜规则必须固定、公开且可重复；除完全相同、无法区分的情景外，结果不得依赖本批情景编号或顺序。
- **FR-007**: 身份分配规则：首批每个情景获得新身份；之后已关联情景继承前驱身份（含被标为歧义的关联，保留歧义标记）；未关联情景获得新身份并记录原因；前一批未关联情景的身份在该处结束。每个情景恰有一个身份，同一身份在同一批次至多出现一次，身份在断链后不得复活。同一回放版本内身份编号确定可重现。
- **FR-008**: 相邻关系以回放清单声明的计划起报序列（首个验收案例为每 12 小时一次）为准。计划批次缺失或单批次计算失败时，该处断链，缺口之后的情景全部获得新身份并注明原因；不跨缺口关联。
- **FR-009**: 每次回放必须是不可变的回放版本，绑定有序输入清单摘要、情景配置、匹配配置、空间权重和软件版本。相同绑定内容及构建产物重跑得到完全相同的情景、关联、距离和身份；同一有效源码独立重建时核对实际构建身份，并按出生节点键验证数值与身份链的语义复现，不要求构建二进制或由其 hash 派生的版本前缀相同；输入或配置改变时生成新版本并重算整条链，旧版本保留且可查询。同一版本键写入不同内容必须失败。
- **FR-010**: 必须在查询环境中保存回放版本、批次及其状态、情景（物理平均场、成员数、成员占比、身份及分配原因）、相邻批次比较结果（含距离矩阵与未关联项）和关联。保存必须满足：每个情景恰一个身份；每次比较中每个情景至多一条关联；关联只连接同一回放版本中相邻、时间递增的批次。只有全部计划批次均形成明确状态、所有应执行的相邻比较成功、身份分配和发布完整性检查均通过后才能发布。计划批次缺失或输入合法但单批算法无法完成（如秩不足、不能形成指定簇数、未收敛或离散为零），可保存为明确的 missing/failed 状态并按 FR-008 断链。元数据不兼容、非法输入、来源或扩展身份核验失败、匹配失败、未知执行错误或发布失败必须阻止整次回放发布，正式历史表不留下该版本的部分记录。
- **FR-011**: 必须提供查询调用入口，每行显式给出前后两批情景、权重和配置并返回 FR-005 至 FR-006 的结果；该入口不查找历史、不分配身份。现有单批次情景入口的行为和输出保持不变。
- **FR-012**: 本规格边界情况中的非法输入、非法配置和数值错误必须明确失败并说明原因及位置；失败不得终止宿主，同一会话后续合法调用须成功；包含非法行的查询整体判失败，不记为部分成功。
- **FR-013**: 必须使用 WeatherBench2 IFS ENS 的 8 个真实批次作为首个真实案例：起报 2020-01-01 00 UTC 至 2020-01-04 12 UTC，每 12 小时一次；共同有效时刻 2020-01-05 00 UTC；时效 96 至 12 小时；每批 50 个扰动成员；2 米气温，单位 K；沿用 M0 的 3×3 欧洲区域格点。样本清单必须记录源对象、对象版本、源块与载荷校验值、坐标、成员标签、获取时间和许可限制，并可从清单恢复。
- **FR-014**: 真实样本必须经独立的样本准备步骤转为固定 OM 对象，记录轴顺序、坐标、成员标签、单位、有效时刻与起报时间，并采用无损编码。源解码、独立 OM 读取和 DuckOMO 查询三条路径得到的每个成员 × 格点数值必须逐值相同。该路径必须表述为“真实集合转 OM 后接入”，不得称为原生公开 OM 数据接入。
- **FR-015**: 首个接入目标为 DuckOMO `v0.3.5-rc.1` 对应 DuckDB 1.5.5、Linux ARM64 的发布包，`v0.3.4` 同平台发布包作为对照。加载前必须核对发布包与扩展校验值；DuckOMO 与本项目扩展须在同一查询连接中完成读取到保存的全流程。两版本读取的成员矩阵与追踪结果必须一致。验收只覆盖读取本地冻结的 OM 文件。不得把本地构建产物冒充发布包，不宣称远程读取、请求合并、异步加速或 DuckDB 2.0 支持。
- **FR-016**: 必须提供以下合成用例，每类至少一个，并用独立的小规模穷举参考核对关联集合与目标值：编号置换；全部超门槛及恰等于门槛；情景数变化（如 2→3→2）；门槛参与求解的反例（候选距离矩阵 `[[0,4],[4,6]]`、门槛 5 时应得到两条距离为 4 的关联）；完全对称歧义；接近并列；远离边界与接近边界的轻微扰动；手算的加权距离与权重整体缩放；元数据不一致；含新出现与结束的多批链；缺批与单批失败；同版本重跑与冲突写入；全部非法输入类别及失败回放不留残余。真实样本验证与合成验证分别记录，不能互相替代。
- **FR-017**: 必须对真实 8 批案例生成回放报告，并执行扰动与门槛敏感性实验。扰动幅度、门槛比例系数范围和稳定性判定规则必须在执行前冻结；分别报告仅匹配层面的扰动和从成员数据开始的完整流程扰动，以区分单批次情景变化与关联变化。另须以每批 2 个和 4 个情景各做一次完整回放（各为独立回放版本），报告身份链对情景数的敏感程度；若某批在该情景数下无法计算，按 FR-008 断链并记录。报告不得宣称校准概率、预报技巧或气象意义上的情景新生与消亡。
- **FR-018**: 匹配计算必须能脱离查询宿主独立执行，不访问网络、不读取历史状态、不调用参考工具。必须在断网且无参考工具的最小环境中，用本地已冻结的 OM 样本实际完成整条回放及同连接错误恢复。
- **FR-019**: 必须记录样本准备、参考、构建、DuckOMO、宿主及运行环境的具体版本和重建步骤，优先复用 M1 版本组合，变更须说明原因和重跑范围。M1 原有验收必须在 M2 代码基线上重跑并通过。
- **FR-020**: 必须测量真实 8 批回放中样本转换、OM 读取、单批次情景计算、跨批次匹配和历史保存各环节的墙钟时间与峰值内存，标明冷启动与已加载范围；无法分离的成本明确标记，不设未经测量的吞吐承诺。
- **FR-021**: 必须提供可执行示例、复跑指南及覆盖全部功能要求和成功标准的验收报告。所有必要项实际通过后才能判定 M2 完成；失败、未执行项、未覆盖平台、样本许可限制和已知解释边界均须明确记录。

### Key Entities *(include if feature involves data)*

- **追踪任务**：一个模型、变量、区域、有序格点清单、单位、特征版本和共同有效时刻的组合，以及计划起报序列。
- **起报批次**：追踪任务中的一次起报，关联起报时间、预报时效、输入来源与校验值、可用状态及其单批次情景结果。
- **情景节点**：某批次中的一个情景，含本批编号、物理平均场、成员数、成员占比和持续身份；本批编号只在本批内有效。
- **相邻比较**：同一回放版本中两个相邻批次之间的一次匹配，含候选距离矩阵、两批离散与换算门槛、可关联标记、目标值、未关联项及原因和配置。
- **关联**：相邻比较中前后两个情景节点的一对一关系，含距离、可替代程度和歧义标记。
- **持续身份**：沿关联链延续的情景标识，记录出生批次、结束位置和分配原因；不表示物理上的新生或消亡。
- **回放版本**：绑定有序输入清单、全部配置、权重与软件版本的一次不可变追踪结果。
- **OM 样本**：由真实来源转换而来的固定数据对象，带来源、轴语义、单位、编码和逐值对照证据。
- **验收记录**：绑定输入、配置、版本、预期、实际结果和逐项状态的可复核证据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 8 个真实批次可从记录途径恢复并转为 OM 样本；3,600 个成员 × 格点数值在源解码、独立 OM 读取与 DuckOMO 查询三条路径间 100% 逐值相同，每批恰为 50 个成员 × 9 个格点。
- **SC-002**: 真实 8 批回放在同一查询连接中完成读取、情景计算、匹配和保存，产生 8 批情景与 7 次相邻比较；100% 情景恰有一个身份，每次比较都有完整候选距离矩阵和未关联记录。
- **SC-003**: 同一回放版本在至少三个独立进程中重跑，情景、关联、距离和身份编号 100% 相同；目标与对照 DuckOMO 版本得到的成员矩阵和追踪结果 100% 相同，两者发布包校验值与官方发布记录一致。
- **SC-004**: 全部约定合成用例的关联集合和目标值与穷举参考 100% 一致；门槛反例得到两条距离为 4 的关联；编号置换用例在所有测试排列下得到相同的节点级关系（完全对称用例除外，且其歧义标记 100% 正确）。
- **SC-005**: 每类非法输入、非法配置和数值错误 100% 明确拒绝，失败后的同会话合法调用全部成功；失败回放留下的部分记录数为 0；同版本冲突写入 100% 被拒绝。
- **SC-006**: 满足冻结证书的相邻批次对，其映射后的关联集合变化数为 0。整链身份单独验收：只有出生节点对应关系一致且通向该节点的上游继承关系均保持一致时，才要求逻辑身份不变；不同回放版本按出生节点键比较，不直接比较版本前缀。接近边界、评估映射歧义、上游关联翻转或单批计算失败导致的变化均分别记录；100% 接近边界翻转附距离余量。冻结的门槛比例系数范围内每个取值以及每批 2、3、4 个情景三种设定都有身份链结果。
- **SC-007**: 在断网且无参考工具的最小环境中，本地样本的完整回放结果与正常环境一致，错误恢复全部通过。
- **SC-008**: 各环节耗时与峰值内存均有记录；M1 原有验收重跑通过；一个独立的全新检出目录能重现真实回放结果；证据索引覆盖 100% 功能要求和成功标准。

## Assumptions

### 已确定的项目约束与用户决定

- 用户已确认：短中期区域 2 米气温集合；单模型、固定区域、单一有效时刻、连续 4–8 次起报；复用 M1 情景计算；以物理平均场匹配；允许拒绝的一对一关联；在查询环境保存持续身份。
- 用户已接受首条接入路径为 WeatherBench2 真实集合转 OM 后经最新 DuckOMO 读取。Dynamical GEFS 0.5° 等更细网格来源留作后续扩展。
- 核心计算使用原生 Rust 或 Rust 包，独立于查询宿主；Python 等仅用于样本准备和独立参考，不进入核心运行路径。
- 当前 constitution 仍为未填写模板，不从示例推导治理要求。

### 匹配与回放规则（标注“已确认”的来自 2026-10-29 澄清，其余为默认值）

- 匹配目标采用“先最多关联条数、再最小总距离”，不引入未关联代价参数（已确认）。代价：可能为多延续一个情景而牺牲另一个更近的对应关系；报告中的可替代程度用于暴露这种情况。
- 完全并列的最优组合仍按固定规则选出并继承身份，但标为歧义；接近并列只报告差距，本阶段不设因歧义拒绝关联的门槛（已确认）。
- 关联门槛相对每对批次的集合离散尺度设定（已确认），使长短时效批次间的严格程度可比；离散口径用全体成员对集合平均场的加权均方根偏差、两批取平均（默认值）。
- 真实案例主结果每批 3 个情景，2 个与 4 个情景作敏感性对照（已确认）。
- 回放版本不可变；补插批次或修改配置生成新版本，本阶段不承诺跨版本永久不变的身份。
- 相邻关系按计划起报序列定义；缺批即断链，不设跨缺口重连的最大间隔。
- 门槛比例系数的具体数值、扰动幅度和系数敏感性范围由技术规划结合合成用例和真实样本距离分布确定，并在验收运行前冻结。

### 范围与已知限制

- WeatherBench2 样本是约 5.625° 的粗分辨率再网格化产品，3×3 区域适合验证追踪流程，不能用于评价细尺度天气结构；样本仅含扰动成员，不含控制成员。
- 样本派生数值（包括 OM 对象）的再分发许可未落实，仓库只提交清单、恢复和转换步骤；首次恢复需要访问记录的来源。原始历史可用时间未知，本案例不能作为无未来信息泄漏的业务回测。
- 本阶段读取本地冻结的 OM 对象；远程读取、异步读取性能、DuckDB 2.0、其他平台、WASM 和扩展签名发布不属于验收范围。
- 分裂与合并等多对多关系、自动门槛学习、自动情景数、多变量或时间窗口、多模型、重网格、概率校准和预测收益验证留在后续阶段。
- 不新增常驻服务、通用调度器或通用格式转换平台；OM 转换只服务于固定验证样本。
- M1 设计文档中已发现与实际实现不一致的描述（如“尚未实现”、字段命名），由技术规划阶段同步，不改变 M1 已验收行为。
